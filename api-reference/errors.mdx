## 判断请求是否出错

先检查响应的 HTTP 状态码。所有非 `2xx` 状态码均表示请求错误；`2xx` 指 `200`–`299`。

收到非 `2xx` 响应时，按错误响应处理，不要将响应体作为正常的任务对象或视频文件解析。读取响应体中的错误原因，再决定如何处理请求。

## 错误响应示例

以下为视频生成提交接口返回 HTTP `400` 时的“输入错误”示例。

```json
{
  "code": "plugin_request_invalid",
  "message": "plugin gxc@0.11.0-test3 hook buildSubmitRequest failed: Error: 输入错误，Invalid video request: /seconds must be <= 30; /resolution must be equal to one of the allowed values at assertValid (gxc.js:4918:11)",
  "data": null
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | string | 错误标识，示例为 `plugin_request_invalid` |
| `message` | string | 具体错误原因，可能包含插件版本、参数路径和校验信息 |
| `data` | null | 示例中为 `null`，不包含任务数据 |

该示例表示提交参数未通过模型校验：`seconds` 超过 30 秒，且 `resolution` 不在允许值中。请根据对应模型文档修正参数后重新提交。消息中的插件版本、文件名和行号可能随版本变化，请勿依赖完整消息文本判断错误类型。

不同错误的响应结构和消息可能变化，包括使用嵌套的 `error` 对象。若响应体无法解析为上述 JSON 结构，仍以非 `2xx` 状态码判定请求错误，并保留 HTTP 状态码和原始响应供排查。

## 区分请求错误与任务失败

视频生成是异步任务。HTTP 请求成功不代表视频已经生成成功。

| 场景 | 判断方式 | 处理方式 |
| --- | --- | --- |
| 请求错误 | HTTP 状态码非 `2xx` | 读取错误原因，修正请求或处理服务异常 |
| 任务生成中 | HTTP 状态码为 `2xx`，任务 `status` 为 `queued` 或 `in_progress` | 保存任务 `id`，继续查询 |
| 任务成功 | HTTP 状态码为 `2xx`，任务 `status` 为 `completed` | 下载生成结果 |
| 任务失败 | HTTP 状态码为 `2xx`，任务 `status` 为 `failed` | 读取任务响应的 `error.message`，没有原因时 `error` 可能为 `null` |
| 任务状态未知 | HTTP 状态码为 `2xx`，任务 `status` 为 `unknown` | 使用同一任务 `id` 继续查询确认 |

提交任务后，使用返回的 `id` [查询视频任务](/api-reference/videos/retrieve)，根据任务状态处理结果。不要仅凭 HTTP `200` 判断生成成功。
